# 학교 민원 분류 에이전트 (민원대응팀용)

민원대응팀이 접수한 민원 내용을 텍스트로 입력하면 **처리 방향을 분류**하고, 그 근거를
학교 민원 처리 매뉴얼 PDF에서 찾아 보여 준다. 근거는 LLM이 아니라 매뉴얼 색인에서만 나온다.
자동 판정은 후보 제시용이며 최종 판단은 학교장(민원대응팀)이 한다. 설계 원칙·DB·보안 기준은 [CLAUDE.md](../../CLAUDE.md)를 본다.

## 구조
```
입력(웹 화면 web.py / 터미널 __main__.py / POST /api/classify)
  -> service.py   매뉴얼 색인·LLM·DB 연결을 한 번만 만들고, 요청마다 classify() 호출
  -> pipeline.py  개인정보 마스킹 -> 순화문(soften.py) -> 과거 이력·악성 반복(store.py, similarity.py) -> 규칙 판정(rules.py) -> 분기
                  분기: 거부·종결 가능 / 일반 처리 / 악성 의심(이첩 검토)
                  근거: anchor 문장으로 매뉴얼 색인 검색(manual_index.py, retriever.py)
                  부가: 지금 할 일(tasks.py) · 학사일정 답변(schedule.py) · 담임 전달 · 가정통신문 연계(notices.py)
  -> review.py    검토 루프(최대 3바퀴): 판정↔이력 점검, 약한 근거 재검색·보강. 분기는 바꾸지 않음
  -> store.py     DB 저장 / highlight.py 결과 화면 + 형광펜 PDF / transfer.py 이첩 보고서(.hwpx)
```

## 웹 화면 실행
```bash
pip install -r requirements.txt
cp .env.example .env                          # 필요한 값만 채운다 (모두 선택)
# data/ 폴더에 학교민원처리매뉴얼.pdf 를 넣는다 (저장소에 올리지 않음)
python -m agent.complaint.web --llm none      # 규칙 기반, 모델 없이 바로 실행
# 브라우저에서 http://127.0.0.1:8000 접속
python samples/seed_demo_db.py --reset        # (선택) 예시 민원 39건 + 시즌 분석용 지난 1년 치로 DB를 새로 채움. 서버를 끈 뒤 실행
```
- **머리줄**: [민원 목록] [분석] 탭과 [＋ 새 민원 입력] 버튼(어느 화면에서나 창으로 열림).
- **민원 목록(`/`)**: 처리할 일 요약 숫자(진행 중·기한 초과·담임 전달 대기·가정통신문 전달 필요, 누르면 걸러짐), 조회 조건, 목록.
- **분석(`/analysis`)**: 처리 상태·분류 그래프, 부서별 민원 현황과 개선 검토 부서, 시즌별 민원 키워드와 가정통신문 계획.
- **새 민원 입력**: 민원 내용(필수). 학생 이름·학년반(305 등)·접수 시각·통화 시간·"시험 입력(저장 안 함)"은 접힌 '추가 정보'에 있다.
  분류하면 저장되고 상세 화면으로 이동한다. 운영에서는 시스템이 원문과 함께 `POST /api/classify`로 보낸다.
- **민원 상세(`/complaints/<번호>`)**: 왼쪽은 민원 내용(순화문, [원문 보기]) → 담당자 참고(LLM이 쓴 경우) → 답변 초안(복사) → 접힌 참고 자료
  (지금 할 일, 분류 사유, 비슷한 다른 학생 민원, 처리 경과, 매뉴얼 근거·PDF). 오른쪽은 분류·긴급도·담당 부서·기한, 처리 상태(상태·처리자·메모 기록),
  상위기관 이첩(보고서 내려받기), 과거 이력, 담임 교사 전달([전달함으로 표시]).
  E1 같은 근거 번호에 마우스를 올리면 매뉴얼 문장이 말풍선으로 보인다. 지금 할 일에는 근거 번호를 붙이지 않는다.
- 학생 이름과 학년반을 둘 다 비우면 '학생 미상'으로 저장하고 학생 기준 이력 판단은 하지 않는다. 접수 시각을 비우면 업무시간 외 판정, 통화 시간을 비우면 20분 초과 판정을 하지 않는다.
- 이 사이트가 공식 접수 창구라서 '공식 창구 외 경로' 민원은 없다고 본다. 교직원 개인 번호·카톡을 묻는 글만 거부 가능이며 이때만 공식 창구 안내가 붙는다.
- 기본은 내 컴퓨터(127.0.0.1)에서만 접속된다. 다른 PC에서 쓰려면 `--host 0.0.0.0`을 주되, 인증이 없으므로 신뢰할 수 있는 내부망에서만 쓴다.
- **결과 파일**: 저장된 민원은 `out/web/complaint-<번호>/evidence_highlighted.pdf`(근거 형광펜 PDF)만 남는다. 시험 입력은 가장 최근 1건만 `out/web/web-…/`에 남는다.
  `out/`은 다시 만들 수 있어 지워도 된다.
- 프로그램 연동용: `POST /api/classify` 에 JSON(`text`, `student`, `class_no`, `received_at`, `call_minutes`)을 보내면 JSON 결과를 준다. `GET /api/notices`는 가정통신문 계획.

## 검토 루프
분류 직후 최대 3바퀴 돈다(`review.py`). 이력과 판정이 어긋난 곳(학생 미상 악성 의심, 유사도 경계, 과거 악성 이력인데 일반 처리 등)을 '담당자 참고'에 올리고,
규칙 문구와 잘 맞지 않는 매뉴얼 근거는 재검색해 보강한다. 재검색어는 LLM이 있으면 LLM이, 없으면 규칙이 만든다. 판정은 바꾸지 않고 `needs_human_review`만 켠다.
상세 기록은 민원 상세의 참고 자료 > '검토 기록'에서 본다.

## 민원 DB
처리한 민원은 `DATABASE_URL`(기본 SQLite `data/complaints.sqlite`)에 저장된다. 테이블은 처음 실행할 때 자동으로 만들어진다.

| 테이블 | 내용 |
|---|---|
| `students` | 민원 대상 학생. 이름 + 학년반이 같으면 같은 학생 |
| `complaints` | 민원 1건 = 1행. 마스킹된 원문·순화문·분기·긴급도·담당 부서·담당·기한·반복 횟수, 전체 결과(`result_json`), 처리 상태·완료 시각·담임 전달 상태 |
| `complaint_hits` | 민원별로 걸린 거부·악성 규칙(종류, 규칙 키, 라벨, 심각도) |
| `complaint_events` | 민원별 처리 경과(접수, 상태 변경, 메모, 담임 전달 · 시각 · 처리자) |
| 가정통신문 계획·전달 기록 | 시즌 키워드 계획(`notice_plans`)과 전달 기록(`notice_sends`) |

- **이력 판단**(매뉴얼 근거 표는 CLAUDE.md): 종결 직후 재접촉, 과거 악성 이력(재접촉 1·2차 대응), 반복 악성 시 접촉 제한 검토.
  기간은 `HISTORY_WINDOW_DAYS`(180일), "바로"의 기준은 `RECONTACT_HOURS`(24시간)이다.
- **악성 반복(억울한 악성 분류 방지)**: 같은 학생의 **미해결** 민원 중 **악성 특성(심각도 3 이상·확신 규칙)이 있고 이번 민원과 유사도가 임계값 이상**인 것이
  이번 포함 3건 이상일 때만 악성 의심이다. 유사도는 LLM이 같은 쌍을 `REPEAT_SIM_SAMPLES`(3)번 평가한 중앙값, LLM이 없으면 낱말 겹침(자카드)이며,
  임계값은 `REPEAT_SIM_THRESHOLD`(0.8)다. 평범한 문의를 반복한 것은 악성이 아니라 기존 '종결 가능' 규칙으로만 처리한다.
- SQL DB(PostgreSQL·MySQL 등)로 바꾸려면 `.env`의 `DATABASE_URL`만 바꾼다. Upstash(Redis 계열)는 이 주소로 붙지 않는다(CLAUDE.md 참고).
- 저장되는 원문은 전화번호·주민번호·이메일이 마스킹된 텍스트이며, 이름은 마스킹하지 않는다.

## 터미널 실행
```bash
python -m agent.complaint --demo --llm none
python -m agent.complaint --text "개인 번호 알려주세요" --student 홍길동 --class-no 305 --received-at 2026-10-30T22:10 --llm none
```
결과는 `out/caseNN/`에 `report.html`·`result.json`·PDF로 저장된다.

## LLM 연결 (선택)
`.env`에 OpenAI 호환 서버 정보를 넣는다(`.env.example` 참고): `LLM_BASE_URL`, `LLM_MODEL`, `LLM_API_KEY`.
LLM은 (1) 악성 여부 2차 의견 (2) 답변 초안(+담당자 참고) (3) 민원 원문 순화 (4) 유사도 평가에 쓰이고, 규칙이 잡은 판정을 뒤집지 못한다.
존재하지 않는 근거 번호를 대면 초안을 버리고 기본 문구를 쓴다. `--llm auto`(기본)는 연결이 안 되면 규칙 기반으로 넘어가고, `--llm on`은 연결 실패 시 오류로 멈춘다.
민원 원문(마스킹 후, 이름 포함)이 LLM 서버로 전송되므로 외부 서비스를 쓸 때는 개인정보 처리 기준을 확인한다.
